# Как работает тестировщик

Программа торговли, сторож, заявки, позиции и пользовательский поток Binance в этом коде не сделаны. Тестировщик на биржу ордера не отправляет.

Запуск из корня репозитория. Перед первым разом поставить окружение счёта:

```
python3 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements.txt
```

Дальше двумя процессами:

1. `npm run tester` — Python API и воркер на `http://127.0.0.1:8787`.
2. `npm run tester:web` — экран React на `http://127.0.0.1:5173`.

Сетку, свечи и очередь считает Python. Node нужен только чтобы отдать экран React. Ряд и результаты пишутся в папку `data/` в корне. Пока интерфейс не собран командой `npm run build:web`, адрес `8787` без второго процесса показывает только подсказку открыть `5173`.

## Идея

Открыть «Идея». В списке плагинов доступно только «Пересечение скользящих» (`ma-cross`). «Полосы Боллинджера» и «Пролив от средней линии Боллинджера» видны и не выбираются.

Вписать имя и текст правила своими словами, нажать «Записать идею». Идея появляется в списке и становится текущей. «Обновить идею» меняет ту же запись. Пустое имя, пустой текст или незарегистрированный плагин сервер отклоняет, текст ошибки виден на экране.

## Данные

Открыть «Данные». В полях заранее стоят `BTCUSDT` и `5m`: это пример, оба поля меняются. Таймфрейм выбирается из списка USD-M. Даты задаёт пользователь, пустыми они не подставляются.

«Загрузить» при заполненных датах качает публичные свечи `https://fapi.binance.com/fapi/v1/klines` и правила символа с `fapi/v1/exchangeInfo`. Ключ API не спрашивается. Пока идёт загрузка, статус «качается» и растёт число баров. В конце статус «скачан», видны границы файла, число баров в выбранных датах, число дыр и первые дыры, минимальный лот, шаг лота и шаг цены.

Повторная загрузка того же символа и таймфрейма не скачивает заново уже лежащий кусок: добирается только недостающий край. Между страницами свечей пауза 150 мс. Ошибка биржи остаётся на карточке ряда.

Дыра — разрыв времени открытия больше полутора интервалов. В карточке не больше 200 дыр, счётчик показывает полное число. Шаг цены на экране есть и в расчёте сделки не участвует. Объём режется вниз до шага лота; если шаг неизвестен, объём равен размеру заявки, делённому на цену входа.

## Сетка

Открыть «Сетка». Кнопка «Пресет „MA, как на видео“» заполняет:

- типы быстрой и медленной: SMA и EMA;
- период быстрой: 10…350, шаг 2 (171 значение);
- период медленной: шаг 5, начало и конец пустые;
- смещение: 0…2, шаг 0.1 (21 значение);
- время жизни: 1…10, шаг 1;
- тейк: 1…10, шаг 0.5 (19 значений);
- стоп: те же 1…10 и шаг 0.5, как копия приёма тейка, не как отдельное число из спеки;
- пауза сигналов: одно значение 0;
- направление: long, short, both;
- пересечение: только direct;
- выход: только tp_sl.

Под полями, для которых в спеке нет точного числа, видна оговорка. Пока период медленной пустой, вместо произведения написано, какое поле заполнить, и «Запустить прогон» не работает.

Когда все диапазоны заполнены, на карточке формула: подпись оси, число значений, знак умножения, затем три числа — без правила `fastPeriod < slowPeriod`, к прогону, отсечено правилом. Эти числа приходят с сервера. Пока какое-то поле пустое, запрос не уходит и на карточке написано, какое поле заполнить. Если сервер не запущен, на карточке виден текст ошибки, «Оценить скорость» и «Запустить прогон» выключены. Галочка правила включена и снимается. Равные периоды при включённом правиле в прогон не попадают.

Депозит `1000`, порог остановки `25`, размер заявки `1000` стоят как примеры и редактируются. Плечо стоит `1`, в сетку не входит. Сигнал по закрытию бара отдельно не выключается.

«Оценить скорость» гоняет одну первую комбинацию на выбранном ряде и показывает миллисекунды, комбинации в минуту и оценку полного перебора. Пока оценки нет, «Запустить прогон» выключена. Смена сетки оценку сбрасывает. На время оценки API ждёт окончания этой одной комбинации.

«Запустить прогон» ставит задачу в очередь и пишет, что состояние на экране «Прогон». Ряд и даты берутся с экрана «Данные».

## Прогон

Экран раз в секунду обновляет очередь. У открытого прогона видны: досчитано до конца истории, оборвано по просадке, ещё не посчитано, скорость в комбинациях в минуту и остаток времени по этой скорости.

«Остановить очередь» переводит queued или running в остановлен. Уже записанные строки остаются. Воркер после падения снова берёт незавершённый прогон с последней сохранённой комбинации, старые строки не стирает. Остановка проверяется пачкой по 20 комбинаций.

Чужой `strategyId` и пустая сетка в очередь не попадают.

## Что считает комбинация

Один и тот же плагин `ma-cross` готовит сигнал и отвечает на закрытии бара. Отдельной ветки «если стратегия — скользящие» в переборе нет: движок исполняет действия плагина.

Пересечение считается по закрытиям. Снизу вверх: на прошлом баре быстрая была не выше медленной, на текущем стала строго выше. Сверху вниз — зеркало. Пока средняя ещё не посчитана, пересечения нет.

Прямой режим: пересечение вверх — лонг, вниз — шорт. Обратный меняет стороны. Направление long или short отбрасывает чужую сторону и не тратит паузу между сигналами. Пауза `N` запрещает новый взятый сигнал на ближайших `N` барах после взятого. Ноль паузу не ставит.

Вход — лимитка. Для лонга цена = закрытие × (1 − смещение / 100), для шорта закрытие × (1 + смещение / 100). Смещение 0 совпадает с закрытием и исполняется на этом закрытии. Смещение больше нуля ждёт касания на следующих барах, не дольше `lifetimeBars`; на последнем баре без касания заявка снимается. Новая лимитка заменяет несработавшую.

Тейк и стоп в процентах от цены лимитки. В режиме тейка и стопа оба стоят. В режиме переворота тейка нет, стоп остаётся, противоположное пересечение закрывает позицию по закрытию бара и открывает противоположную по тому же закрытию. Пока позиция открыта, новый вход в режиме тейка и стопа не берётся.

На баре, где лимитка со смещением только что исполнилась, может сработать стоп, тейк на этом баре не берётся. Если стоп и тейк задеты одним более поздним баром, в сделку идёт стоп. Защита входа по закрытию включается со следующего бара.

Объём = размер заявки / цена входа, затем вниз до шага лота. Меньше минимального лота сделка не открывается. Плечо в прибыль не умножается. Комиссии нет.

`Profit` — сумма закрытых сделок в валюте депозита. Незакрытая в конце истории позиция в `Profit` и в число сделок не входит; её просадка видна в `MaxDraw` и в худшем незакрытом просаде. `ProfitFact` = сумма прибыльных сделок / сумма модулей убыточных. Если убытков не было, `ProfitFact` пустой. `Winrate` — доля сделок с прибылью больше нуля, в процентах. Ноль к победам не относится.

`MaxDraw` — наибольшее падение от пика капитала по закрытиям до худшей цены бара, в деньгах депозита. `MaxDrawPct` — это падение в процентах от стартового депозита. Ранняя остановка другая: она сравнивает худшую оценку капитала с стартовым депозитом, не с пиком. Порог включается: при 25 и депозите 1000 остановка на оценке 750 и ниже. Оборванная строка остаётся, причина начинается с «просадка от стартового депозита». Месяцы после месяца остановки пустые, это не нули. Месяцы считаются в UTC по времени закрытия сделки.

Доля плюсовых месяцев — среди уже посчитанных месяцев. Доля лучшего месяца — его прибыль к сумме помесячной прибыли, если сумма больше нуля.

Типы средних: SMA, EMA, SMMA (она же RMA), WMA, VWMA. VWMA берёт объём свечи.

## Таблица

Открыть прогон на экране «Прогон», затем «Таблица». Вкладка «Досчитанные» показывает строки со статусом done. «Отброшено» показывает оборванные по просадке и снятые порогом. Оборванная строка в первой колонке содержит причину.

Колонка `orderLife` — это `lifetimeBars` конфига. Рядом видны `MaxDrawAt`, `WorstTrade`, `WorstTradeAt`, `WorstOpen`, `WorstOpenAt`, `positiveMonthShare`, `bestMonthShare`. Заголовок метрики сортирует. Фильтры ProfitFact, MaxDrawPct, число сделок и доля плюсовых месяцев применяются кнопкой «Фильтр» и строки не удаляют.

Зелёный / жёлтый / красный у `Profit` и `ProfitFact` — верхняя, средняя и нижняя треть досчитанных строк этого прогона. Пока досчитанных строк меньше трёх, заливки нет. Порога «600%» в заливке нет.

Клик по строке открывает карточку и полоски помесячной прибыли. Пустой месяц без расчёта — серая полоска. Месяц максимальной просадки и месяц худшей сделки обведены. «Показать месяцы» добавляет помесячные числа в таблицу.

Порог: метрика, `>=` или `<=`, число, «Переложить не прошедшие». Не прошедшие done-строки уходят в «Отброшено» с причиной `порог …`. «Вернуть порог» возвращает только их. Оборванные по просадке этой кнопкой не становятся снова досчитанными.

«xlsx» скачивает текущий фильтр. Больше 50 000 строк сервер в файл не кладёт и пишет ошибку. В файле колонка времени жизни называется `orderLife`.

Галочки помнятся для экрана «Уточнение». «В черновик конфига» берёт только done-строки. «В сводную» просит имя, вид «исследовательская» или «рабочая» и группу «короткие» или «старшие».

## Уточнение

На «Уточнение» попадают отмеченные строки. Для каждой числовой оси видны минимум и максимум выбранных значений, шаг и запас. У тейка и стопа шаг по умолчанию `0.3`, запас `0`. «Запустить уточнение» создаёт новый прогон со ссылкой на родительский. На экране «Прогон» у него написано, что это уточнение.

## План гипотез

Доска на 63 ячейки, семь колонок как в спеке. У ячейки подпись направления и «вар N». Смена статуса только записывает статус: не запускалась, в очереди, идёт, есть кандидаты, отброшена. Запуск ячейки правила не подставляет: соответствия вар 1 / вар 2 / вар 3 в спеке нет. Колонки со второй по седьмую помечены «Плагина нет» и прогон не создают.

Шесть кнопок «В очередь» ставят прогон `ma-cross` с текущей сеткой. Подставляются только названные оси:

1. direct, tp_sl, both.
2. direct, flip_on_cross, both. Диапазон стопа не подменяется.
3. direct, tp_sl, long.
4. direct, tp_sl, short.
5. reverse и both. Выход остаётся тем, что включено на сетке.
6. direction short. Символ, который начинается с `BTC`, сервер отклоняет. Список альтов не подставляется.

Остальные диапазоны сетки остаются как на экране «Сетка».

## Передача

«Передача» показывает черновики. У черновика статус `draft`, символ, таймфрейм, `strategyId` = `ma-cross`, рынок `binance-usd-m`, шаг лота, снимок `Profit`, `ProfitFact`, `Winrate`, `Trades`, `MaxDraw`, интервал истории, порог остановки и id прогона. Параметры плагина лежат в `params`, включая `entryOnClose: true`. Кнопки «принять» нет: торговля этот черновик не забирает.

Сводная с этого экрана скачивается в xlsx.

## Чего код намеренно не делает

- Не ведёт заявки, позиции, поток пользователя и хедж-счёт.
- Не поднимает сторожа и экраны торговли.
- Не реализует RSI, MACD, дельту, Боллинджера и пролив.
- Не связывает «вар N» с правилом входа.
- Не подставляет верх и низ периода медленной средней.
- Не считает комиссию и проскальзывание.
- Не округляет цену до шага цены.
- Не перебирает плечо и размер заявки.
- Не скрывает оборванную строку без следа.

## Расхождения с docs/SPEC.md

Имена столбцов правее `MaxDraw` в спеке не заданы. В таблице и xlsx стоят `MaxDrawPct`, `MaxDrawAt`, `WorstTrade`, `WorstTradeAt`, `WorstOpen`, `WorstOpenAt`.

Формула `ProfitFact` в спеке не задана. В коде это сумма прибылей, делённая на сумму модулей убытков; без убытков ячейка пустая.

Цвета — трети готового прогона, не пороги из раздела 3.

Границы стопа в пресете скопированы с первого прохода тейка. Шаг времени жизни в пресете равен 1. Оба места в интерфейсе подписаны.

Путь `fapi/v1/klines` в спеке не назван. Код ходит на публичный USD-M хост `fapi.binance.com`.

Полные названия сводных книг в спеке не записаны. В продукте два вида, исследовательская и рабочая, и две группы таймфреймов, короткие и старшие.
